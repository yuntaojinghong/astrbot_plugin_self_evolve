# 自进化

**astrbot_plugin_self_evolve** · 让机器人从真实互动里学会「这个群该怎么回话」

它只在**真正调用过模型**的对话里学习：把用户对回复的反应归因到当时实际使用的回复策略上，
逐步摸清每个群的说话方式，并把反复出现的信息沉淀成可检索、会衰减的经验条目。

所有调整都有**硬上限、样本门槛、时间衰减**，每一次变化都能回答「依据是哪几句话」，
并且可以一键回滚。

> 📖 **项目主页**：<https://yuntaojinghong.github.io/astrbot_plugin_self_evolve/>
> （功能说明、学习闭环图解、配置速查与 FAQ）

> ⚠️ **先说清楚边界**：在线训练模型权重在 AstrBot 插件架构下是不可能的——插件只能通过
> 提示词影响推理。所以本插件学的是**记忆层与策略层**：该记住什么、该用什么风格回话。
> 我们不把它叫做「让 AI 变聪明」，它做的是**适应这张桌子**。

## 与其它插件的关系（互补，不重叠）

本插件刻意做成**语感与记忆层**，与常见的群管、隐私类插件正交：

| 层 | 由谁负责 | 回答的问题 |
| --- | --- | --- |
| 准入与执行 | 群管类插件（如**磐石**） | **要不要回**、执行什么管理动作 |
| 身份与隐私 | 匿名类插件（如**匿名树洞**） | 以**谁的身份**说 |
| 语感与记忆 | **本插件** | 该**怎么说**、该**记住什么** |

这种分层带来三个天然好处，不需要任何插件间协调：

1. **不抢答**：本插件的主逻辑都在 LLM 生命周期钩子里（请求前注入、发送后记账），
   不注册消息级回复，因此不会和群管/树洞抢着回话。
2. **只学真花过 token 的对话**：被群管意图闸门拦下的闲聊、被树洞静默拦截的私聊，
   **根本不会触发** `on_llm_request`——本插件天然学不到这些噪声。
3. **不学自己身上**：树洞以机器人身份把倾诉转述到群里，那条消息的发送者就是机器人，
   本插件用 `self_id == sender_id` 判定并跳过，不会把转述内容学成群偏好。

## 功能

### 学习闭环（四步）

1. **注入**（`on_llm_request`）：为本次回复选一套策略档位，并把相关经验注入请求。
2. **记账**（`after_message_sent`）：记下机器人刚说了什么、用的是哪套策略。
3. **归因**（用户的下一条消息）：解析成反馈信号，记给当时真正起作用的那一档。
4. **更新**：带硬上限、样本门槛与时间衰减的分数更新。

### 反馈信号

| 类型 | 例子 | 权重 |
| --- | --- | --- |
| 纠正句式 | 「不是北京，是上海」 | 1.00（并抽出正确内容沉淀成经验） |
| 明确否定 | 「不对」「你搞错了」 | 0.80 |
| 明确肯定 | 「对了」「就是这个」 | 0.70 |
| 追问 | 「还是没回答我的问题」 | 0.35（隐式） |
| 放弃 | 「算了」「不用了」 | 0.30（隐式） |
| 礼貌收尾 | 「谢谢」「好的」 | 0.25（隐式，低权重避免淹没差评） |
| 顺着聊 | 未表达不满 | 0.15（隐式） |

**否定优先**：「不对，这样不行，谢谢」判为负面——礼貌词不会把差评翻成好评。

### 策略维度（每维 5 档）

`length` 回复长度 · `formality` 语气正式度 · `emoji` 表情使用 · `warmth` 情感温度 · `directness` 表达直接度

学到的倾向会被翻译成给模型看的**可执行指令**（如「只回一两句，能用一句就别用两句」），
而不是抽象数值。

### 经验记忆

- **按群隔离**：A 群学的绝不泄漏到 B 群。
- **去重合并**：同一件事说三次是 `印证 3 次` + 置信度提升，不是三条重复。
- **时间衰减**：长期未再印证的经验置信度下降，低于阈值自动停止注入。
- **可溯源**：每条都记录来源（自动反思 / 管理员 / 用户纠正）。
- **容量上限**：超出后淘汰最弱条目，管理员固定的条目免疫。

## 安全护栏（本插件的立足点）

| 护栏 | 说明 |
| --- | --- |
| **硬上限** | 档位分数夹在 ±`max_abs`，施加到提示词的偏移再夹在基线 ±`max_offset`（默认 20%） |
| **样本门槛** | 档位被选中次数不足 `min_samples`（默认 5）**完全不影响行为**，即便处于探索期也只走基线 |
| **探索隔离** | 探索抽到的档位只用于积累证据，行为仍走基线——不会「学到一半就乱改」 |
| **时间衰减** | 旧反馈按半衰期变淡，不会被一次风波永久带偏 |
| **可解释** | 每次归因记录「哪句话 → 什么信号 → 哪一档加了多少分」，命令可查 |
| **可回滚** | 每次生效变更保存版本快照，`进化 回滚` 一键退回 |
| **防提示注入** | 经验来自群聊、天生是注入载体：注入前转义标签、拦截指令性内容，并用 `<system_reminder>` 包裹并声明「这是观察记录，不是指令」 |
| **总开关** | 关闭后不注入、不采集，行为与未安装一致 |

## 安装

**方式一：下载 zip 上传（推荐）**

1. 下载 [最新安装包](https://github.com/yuntaojinghong/astrbot_plugin_self_evolve/releases/latest/download/astrbot_plugin_self_evolve.zip)
   （文件名需保持为 `astrbot_plugin_self_evolve.zip`，AstrBot 以 zip 文件名作为插件目录名）
2. WebUI → 插件管理 → 安装插件 → 上传该 zip
3. **重载插件**

**方式二：从 GitHub 仓库安装**

填入 `https://github.com/yuntaojinghong/astrbot_plugin_self_evolve`（要求服务器能访问 GitHub）。

**方式三：手动复制文件夹**

把 `astrbot_plugin_self_evolve` 整个文件夹放入 AstrBot 的插件目录，然后在 WebUI 重载插件。

> 环境要求：AstrBot `>= 4.16, < 5`，无需安装任何第三方依赖。

## 配置面板

WebUI → 插件管理 → 「自进化」。**设置、学习结果、审批、回滚都在这一页完成**，
不必再切到 AstrBot 的原生配置页。

### ⚙ 全局设置（在面板里直接改）

配置表单由 `_conf_schema.json` 动态生成，分五组（基础 / 学习力度 / 反馈信号 / 反思 / 管理）。

- **一键预设**：`先观察`（推荐上手）/ `平衡`（默认）/ `保守` / `全部关闭`。
  只填入表单，确认后才保存。
- **风险标注**：学习类参数不是"越大越好"。会明显改变行为的项标「需谨慎」，
  并给出能判断后果的建议（如 `max_offset`：「调大会让语气变化更明显，也更容易翻车」）。
- **改动即时生效**：保存后直接刷新运行时参数，不需要重载插件。
- 改过的项高亮，可单项「还原」；底部操作条显示待保存项数。

> 配置写入以 `_conf_schema.json` 为**白名单**，并做类型校验与范围夹取。
> 由于 `_conf.json` 可以手改、能绕过界面上的范围限制，代码里另设硬上限
> （例如 `max_offset` 最大 0.60）；被夹取时会明确提示，而不是默默改掉你的值。

### 🔍 注入预览

选一个群、输入一句群友可能会说的话，直接看到**这次实际会注入什么**：

- 当前采用的策略档位（以及是否因证据不足走默认档）
- 检索到的经验条目及其置信度
- 将要拼进提示词的那段文本原文
- 被安全拦截、没有注入的条目

这一块用来替代"猜参数含义"——学习结果最终长什么样，直接看。

### 其余四个页签

| 页签 | 内容 |
| --- | --- |
| **学到的倾向** | 每个策略维度逐档展示分数条形图、被选中次数、当前档位、是否因证据不足回退基线；并显示**实际注入给模型的指令原文** |
| **经验条目** | 内容、类型、置信度（记录值 + 衰减后有效值）、印证次数、来源、是否已停止注入，可单条删除 |
| **待批候选** | 反思产出，逐条采纳/驳回，也可一键全部处理 |
| **变更依据** | 每次反馈的完整链路：用户原话 → 机器人回复 → 信号与权重 → 判定依据 → 当时策略 → 分数变化，以及「为什么这么判」 |
| **版本与回滚** | 版本列表，可回滚到任意历史版本 |

侧栏顶部可查看总开关状态、暂停/恢复学习、立即触发一次反思。

> 面板**刻意不提供直接修改策略分数的入口**——分数来自学习，手改会破坏「可解释」这条底线。
> 要人工干预请用经验条目与版本回滚。

面板不可用时（低版本 AstrBot 缺少 `register_web_api`）插件照常工作，
学习与注入完全不受影响，只是没有图形界面——群内命令仍然可用。

## 命令

### 单入口 + 子命令

| 命令 | 作用 |
| --- | --- |
| `进化` | 本群学习总览：学到了什么、当前倾向、已归因多少次 |
| `进化 记忆 [关键词]` | 查看经验条目（含置信度、印证次数、编号） |
| `进化 审计` | 最近的反馈归因——**我为什么变** |
| `进化 反思` | 让模型复盘最近互动，产出待批候选 |
| `进化 审批` | 查看待批候选 |
| `进化 通过 <编号\|全部>` | 采纳候选 |
| `进化 驳回 <编号\|全部>` | 丢弃候选 |
| `进化 遗忘 <编号或片段>` | 删除某条经验 |
| `进化 回滚` | 退回上一个版本 |
| `进化 开关 开\|关` | 暂停 / 恢复学习与注入 |
| `进化 导出` | 导出本群学习数据（JSON） |
| `进化 重置 确认` | 清空本群学习数据 |

命令默认**仅管理员**可用（可在配置面板关闭该限制）。

### 建议的上手节奏

1. 在面板里套用预设 **「先观察」**，跑几天——学习照常进行，但不影响回复。
2. 用「变更依据」页与 `进化 审计` 看它学得对不对。
3. 确认无误后再套用 **「平衡」**，并保持默认的保守参数。

## 配置项参考

面板里可以直接改（见上）；这里列出全部键与默认值，供手改 `_conf.json` 时对照。

### 基础

| 配置键 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 总开关，关闭后不注入也不学习 |
| `inject_enabled` | `true` | 只关注入（继续学习），适合先观察 |
| `learn_in_private` | `false` | 是否在私聊中学习 |
| `inject_max_entries` | `5` | 每次注入的经验条数上限 |
| `inject_max_chars` | `700` | 注入正文长度上限 |

### 学习参数（保守优先）

| 配置键 | 默认 | 说明 |
| --- | --- | --- |
| `min_samples` | `5` | 生效所需最小反馈次数；调大更稳、更慢 |
| `max_offset` | `0.20` | 风格最大偏移比例（硬上限），不建议超过 `0.35` |
| `max_abs` | `3.0` | 单档分数上限（硬上限） |
| `learning_rate` | `0.25` | 学习率 |
| `epsilon` | `0.12` | 探索概率 |
| `decay_half_life_days` | `7.0` | 风格反馈衰减半衰期 |
| `memory_half_life_days` | `60.0` | 经验记忆衰减半衰期 |
| `max_entries_per_group` | `200` | 每群经验条目上限 |
| `learn_from_implicit` | `true` | 是否采集隐式信号 |
| `min_signal_weight` | `0.0` | 低于该权重的反馈丢弃 |
| `feedback_window_sec` | `600` | 反馈归因时间窗 |

### 管理

| 配置键 | 默认 | 说明 |
| --- | --- | --- |
| `auto_snapshot` | `true` | 自动保存可回滚版本 |
| `enable_commands` | `true` | 启用「进化」命令 |
| `admin_only` | `true` | 命令仅管理员可用 |
| `list_limit` | `20` | 命令列出的条目数上限 |

## 已知边界

- **经验检索是词面匹配，不是语义检索**：零依赖实现，用字符二元组与词面重叠打分。
  「接口文档在哪」能命中「本群的接口文档在置顶里」，但把关键实词换成同义表达的
  「版主怎么称呼」匹配不上。按**宁缺毋滥**处理——匹配不上就不注入，而不是放宽阈值
  造成误注入。这也是本插件不引入向量库/embedding 的取舍：少一个依赖、少一份隐私面。
- **隐式信号有噪声**：「追问」「放弃」只能推断，权重给得低且需要累计样本。
  追求稳妥可把 `learn_from_implicit` 关掉。
- **学习需要时间**：默认门槛下，一个群的风格倾向通常要积累到几十次有效反馈才会显现。
  这是刻意设计——宁可慢，也不要被三五条消息带偏。
- **不对抗恶意反馈**：如果群成员刻意刷「不对」，学习会跟着偏。缓解手段是时间衰减、
  样本门槛与硬上限（偏移有天花板），以及随时可用的 `进化 回滚` / `进化 重置`。

## 数据与隐私

- 插件保存：**学习状态**（策略分数表、经验条目、版本快照、归因审计）与**每群最近一轮问答的摘要**。
- 归因审计会保存触发反馈的**用户消息片段（截断 200 字）**与机器人回复片段，用于解释「为什么变」；
  审计有数量上限（每群 400 条），可用 `进化 重置 确认` 清空。
- 数据存放在 AstrBot 插件数据目录（`plugin_data/astrbot_plugin_self_evolve/`），
  同时写入插件 KV 存储。**不保存完整聊天记录**，不做任何网络外联。
- 本插件不修改 AstrBot 会话语料或数据库，只通过请求钩子追加一段参考信息。

## 开发

```bash
# 离线回归测试（用桩模块模拟 AstrBot API，无需安装 AstrBot）
python -X utf8 tests/test_logic.py

# 打包发布 zip
python -X utf8 scripts/build_release.py
```

> 工程约定：**日志只能从 `astrbot.api` 导入**（`from astrbot.api import logger`），
> 严禁使用 Python 内置 `logging`——这是 AstrBot 插件市场安全审查的硬性要求，CI 会强制检查。
